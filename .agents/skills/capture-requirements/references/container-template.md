# Container issue template

**Title:** `[Feature] <theme> (container)`

**Labels:** `todo`+`enhancement` **or** `question` (same mode as the set)

```markdown
## Summary
<1–2 sentences: the feature theme and player-facing outcome>

## Why
<reason / player need>

## Requirement summary
- Functional: <one short paragraph>
- Non-functional: <budgets or “not affected”>
- UX: <surfaces + criticality, or “not affected”>
- Architectural: <intent + proposed locus>
- Algorithmic / schematic: <or “not affected”>

## Sub-issues
Tracked as GitHub sub-issues (created with this container):
- <title — workstream>
- <…>

## Acceptance (theme)
- [ ] Player-visible outcome works on the scoped platforms
- [ ] Sub-issues cover the agreed workstreams
- [ ] Wiki updated if rules change (only after confirmed follow-up)

## Impact analysis
- Pillars touched: <P1–P5 / REQ-* if known>
- Wiki: <already specified | silent | conflicts — link pages>
- Scope guess: <medium | large>
- Desktop + mobile: <both | scoped>
- Dependencies / risks: <…>

## For agents
- Skill: capture-requirements
- Ambiguity mode: <todo+enhancement | question>
- Related open issues checked: <none or #N…>
```

Optional (only after owner confirms wiki follow-up):

```markdown
## Wiki follow-up
- Pages: <wiki page titles/URLs>
- Change needed: <new or revised rule summary>
```
